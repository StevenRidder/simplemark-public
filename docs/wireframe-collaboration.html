Left · Library
Note scope only. Recent Notes, Untagged, Todo, Today, Pinned, Trash, Folders. Rebuildable views over the Markdown folder — never a second note store. NATIVE-WORKSPACE.md · Library pane
Middle · Notes
One note index. Title, one-line preview, modified time, quiet pin. Header is exactly three things: [Recent Notes ▾] [Search] [New Note]. DESIGN.md §6 · NATIVE-WORKSPACE.md
Right · Document
The primary surface. Rendered, directly editable Markdown. Everything collaborative happens here or floats over here — never beside it permanently. DESIGN.md §6
Not present, by rule
No agent pane, activity sidebar, model picker or chat panel. No permanent activity, chat, agent or inspector rail. DESIGN.md §10.1 · NATIVE-WORKSPACE.md

A stop is not a message. Every operation carries a run id and a generation; interrupting bumps the generation and a superseded generation is refused, not merged. SWITCHBOARD-KERNEL.md §2 calls this the one piece of machinery worth building before the first agent edit lands.

5What an agent may do, by who is present

The constraint keys on presence, because it exists to protect attention — which is also what makes agent-opened notes safe.

Note stateWhat an agent may do
You are editing a paragraphDoes not enter it. Waits, or works in its own scope.
You select and invokeMay edit within that scope, live, with its cursor visible.
Two humans active in a sectionOffers a compact suggestion, or works elsewhere.
No human participatingMay work document-wide inline — journaled, attributed, revertible, budgeted.
Document-wide work, humans presentDeferred to a quiet review item. Never an unsolicited inline edit.
Nothing granted, nothing askedNothing happens.

From the CHI 2026 study behind COLLABORATION.md §5.7: autonomous document-wide intervention produced overload, and ~23% of participants did not feel in control of the text. Humans never need a lease to type — fences and scopes constrain only an agent’s right to commit.
